# Review Profile Integration Patch v1

## Purpose

Prepare the existing `profile.html` for the canonical first-party review contract without rewriting or reconstructing the large one-line profile file.

## Target

`profile.html`, section `#own` / first-party reviews.

## Required replacement

Replace only the current disabled review form markup inside `#own` with the schema-v1 browser fields:

- `location_id`
- `author_display_name`
- `author_email`
- `rating` (1–5)
- `body` (50–5000 characters)
- `experience_confirmed`
- `terms_accepted`
- `privacy_accepted`

## Fields that must be removed

The existing prototype fields equivalent to:

- `Что понравилось`
- `Что можно улучшить`
- the single combined consent checkbox

must not be submitted by the browser because schema v1 uses `additionalProperties: false` and three separate consent flags.

## Protected/service fields

The browser must not authoritatively supply:

- `company_slug`
- `request_id`
- Turnstile verification state
- moderation/publication status
- provenance fields generated by the protected layer

These are created/validated by the protected integration layer.

## Published review block

The same `#own` section must contain an empty published-review state until a real moderated review exists. When a review is published, use the canonical semantic structure:

```html
<section id="reviews">
  <article class="review" id="review-REVIEW_ID" data-review-id="REVIEW_ID">
    <header>
      <h3>AUTHOR_DISPLAY_NAME</h3>
      <div aria-label="Оценка: N из 5">★★★★★</div>
      <time datetime="YYYY-MM-DD">DATE</time>
    </header>
    <p class="review-body">PUBLISHED_REVIEW_TEXT</p>
    <footer>
      <span>Источник: Отзыв.com</span>
      <span>Статус: опубликован</span>
    </footer>
  </article>
</section>
```

This is a structural contract only; no real or fabricated review data is to be inserted during prototype work.

## Machine readability

Published review text must be present in ordinary HTTP-delivered HTML. JSON-LD may be added as a synchronized supplementary representation, but must never be the only copy of the review text.

## Safety

- Keep the current company identity, ratings, branches, services, media, AI and management sections unchanged.
- Keep the profile `noindex,nofollow` prototype status unchanged.
- Do not connect production API, Turnstile, Cloudflare, Supabase, payment or authentication in this patch.
- Do not invent review content.

## Acceptance criteria

1. Existing profile sections remain byte-for-byte unchanged outside the `#own` target.
2. Review form matches schema v1 fields exactly.
3. Three separate consent flags exist.
4. Obsolete plus/minus fields are absent.
5. Published-review empty state remains explicit.
6. Semantic review structure is documented and ready for real publication.
7. No production infrastructure is changed.

## Implementation note

The current `profile.html` is a very large one-line document. The connector cannot safely return the complete file in one editable payload. Therefore this patch is deliberately stored as an exact integration contract instead of risking a destructive whole-file reconstruction.
