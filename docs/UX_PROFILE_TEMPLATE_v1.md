# OTZOVIK — UX / PROFILE TEMPLATE v1.0

Дата: 2026-08-24
Статус: предложенный эталонный UX-шаблон, без кода

## 1. Цель

Создать единый эталонный профиль компании, который одинаково понятен человеку и AI.

Главный принцип интерфейса:

**одна компания → один профиль → один общий список отзывов.**

Отзывы не разделяются на отдельные списки по источникам. Источник является атрибутом каждого отзыва. Темы, тональность и частоты относятся к Analysis, а AI Summary является отдельным вторичным слоем.

## 2. Профиль — порядок блоков

### 2.1 Header
- логотип Отзовика;
- поиск компании;
- действие «Сообщить об ошибке»;
- на профиле — название компании.

### 2.2 Identity
Первый и самый важный блок:
- название компании;
- город / география;
- краткое описание;
- статус независимого профиля;
- verification status;
- при необходимости identity/conflict badge;
- сайт, телефон, маршрут;
- филиалы, если есть.

### 2.3 Source Ratings Matrix
Показываются рейтинги только существующих источников.

Для каждого источника:
- название;
- оценка, если она существует;
- количество отзывов;
- дата/свежесть данных;
- статус источника.

При отсутствии данных показывать «Нет данных», а не «—», чтобы не создавать ощущение сломанного интерфейса.

**Общий рейтинг Отзовика не показывается.**

### 2.4 AI Summary
Отдельный визуальный слой.

Содержит:
- краткую сводку;
- количество отзывов;
- количество источников;
- confidence level;
- период данных, если известен;
- предупреждения о конфликтах/устарелости/спорах;
- обязательный дисклеймер.

AI Summary никогда не выглядит как отзыв клиента и не является рекомендацией.

### 2.5 Analysis
Показывать только данные, которые имеют достаточную доказательную базу:
- повторяющиеся темы;
- положительные/отрицательные темы;
- частоты вида `34/281`;
- распределение оценок;
- свежесть;
- динамику при достаточном объёме данных.

Темы могут использоваться как фильтры общего списка отзывов.

### 2.6 О компании / услуги / филиалы
Информация о компании располагается после AI Summary/Analysis и до основного массива отзывов либо в компактных вкладках/аккордеонах.

На мобильном — progressive disclosure без потери основных данных.

### 2.7 Единый список отзывов
Заголовок: **Отзывы** + общее количество.

Фильтры:
- источник;
- оценка;
- период;
- филиал;
- статус.

Каждая карточка содержит:
- оценку;
- оригинальный текст;
- источник;
- дату оригинального отзыва;
- дату получения/обновления Отзовиком, если известна;
- ссылку на оригинал;
- филиал, если установлен;
- статус оспаривания/проверки, если применимо.

Отзывы отображаются одним списком независимо от источника.

### 2.8 Источники и provenance
Показывать:
- источник;
- количество отзывов;
- рейтинг источника;
- последнее обновление;
- ссылку на источник;
- состояние доступности.

## 3. Главная страница

Главная — короткий лендинг, где реальный профиль компании является главным доказательством продукта.

Порядок:
1. компактный Header;
2. Hero с понятным позиционированием;
3. поиск;
4. живой пример профиля Ортомедии;
5. «Как это работает» в 3–4 шага;
6. для человека / для бизнеса;
7. принципы доверия;
8. CTA «Добавить компанию»;
9. структурированный Footer.

Главная не должна повторять методологию в нескольких длинных секциях.

## 4. Визуальное направление

**Modern AI / Technology + Trust / Editorial.**

Правила:
- много воздуха;
- сильная типографика;
- спокойная цветовая база;
- tabular figures для числовых значений;
- минимум декоративных элементов;
- отсутствие неоновых градиентов;
- отсутствие визуальной подачи Отзовика как рекламного каталога;
- статусы спокойные и информативные.

AI Summary допускает отдельный фон/акцент, но должен визуально отличаться от пользовательских отзывов.

## 5. Основные состояния

### 0 отзывов
Показываем identity и доступные данные компании. В блоке отзывов: «Отзывы пока не собраны». Рейтинги источников — «Нет данных». AI Summary не генерируется.

### 1–4 отзыва
Все отзывы доступны. Общая аналитика скрыта. Summary отсутствует либо показывает недостаточность данных.

### 5–9 отзывов
Показываем единый список и короткий preliminary AI Summary с явной пометкой «мало данных». Темы — только при наличии повторений.

### 10–19 отзывов
Summary доступен с указанием объёма. Аналитика умеренная и осторожная.

### 20–49 отзывов
Полноценный профиль и Analysis.

### 50–99 отзывов
Полноценный профиль с более устойчивой аналитикой.

### 100+ отзывов
Полноценный профиль, расширенные темы и временная динамика при наличии данных.

### Нет одного источника
Источник отображается как «Нет данных» с причиной, если причина известна. Остальные данные не скрываются.

### Конфликт данных
Спокойный, но заметный статус «Обнаружены расхождения». Показывается краткое описание конфликта. AI Summary обязан учитывать конфликт.

### Данные устарели
Показывается «Данные требуют обновления» и дата последнего успешного сбора. Старые данные не выдаются за свежие.

### Компания не подтверждена
«Независимый профиль · Компания не подтвердила данные».

### Компания подтвердила профиль
«Компания подтвердила профиль» + дата, если известна.

### Профиль оспаривается
Заметный информационный баннер. Summary обязан учитывать active dispute.

### Отзыв удалён из исходного источника
Отзыв не должен исчезать бесследно: показывается статус и доступная provenance-информация. Публичное отображение полного snapshot определяется утверждённой политикой хранения.

### Отзыв оспорен
Отзыв остаётся в едином списке с заметкой о статусе. Он не должен визуально выглядеть как обычный бесспорный отзыв.

### Источник временно недоступен
Показываются последние известные данные с датой и статусом недоступности.

### Новая компания / мало данных
Комбинация соответствующих low-volume/new-company состояний. Интерфейс не имитирует полноту.

### Несколько филиалов
Единый профиль и единый список отзывов. Отзывы можно фильтровать по филиалу только там, где связь доказана.

### Возможный дубль / несколько юридических сущностей
Показывается статус возможной связи/проверки. Данные не объединяются молча.

## 6. Mobile UX

Первый экран:
Identity → Source Ratings → AI Summary → ключевые темы.

Далее:
Отзывы → фильтры → О компании/услуги/филиалы → Источники → Методология.

Фильтры допускают bottom-sheet или горизонтальный список.

Жёсткие правила:
- никакого горизонтального overflow;
- AI Summary не должен полностью исчезать в accordion;
- identity, рейтинги, Summary и первые отзывы доступны быстро;
- machine-readable слой не зависит от раскрытия UI-блоков.

## 7. Запрещённые UX-паттерны

- общий «Рейтинг Отзовика» без утверждённой методологии;
- объединение отзывов по источникам в отдельные публичные списки;
- пустые значения рейтингов в виде «—», создающие впечатление ошибки;
- визуальное смешивание AI Summary и пользовательского отзыва;
- рекомендации компании от имени Отзовика;
- скрытие конфликтов, споров или устарелости;
- создание ложного ощущения статистической уверенности при малом объёме данных.

## 8. Критерий готовности шаблона

Шаблон считается UX-готовым, когда один и тот же layout способен без изменения архитектуры показать:
- профиль без отзывов;
- профиль с малым количеством отзывов;
- профиль с сотнями отзывов;
- неполные источники;
- конфликты;
- stale data;
- verification/dispute;
- филиалы;
- identity ambiguity.

Следующий этап после утверждения этого документа: детализация компонентов/wireframes. Код не входит в этот этап.
