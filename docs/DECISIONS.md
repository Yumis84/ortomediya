# Журнал архитектурных решений (ортомедия)

Формат: дата — решение — статус

## 2026-08-24

- Создан репозиторий `Yumis84/ortomediya`.
- Модель: одна компания → единый список всех отзывов.
- `source` = атрибут отзыва.
- FACT → EVIDENCE → ANALYSIS → AI SUMMARY.
- Общий «Рейтинг Отзовика» не рассчитывается.
- Код и дизайн не пишутся до отдельного задания.

### Утверждено Yumis (IDENTITY RESOLUTION)

1. Автоматическое связывание только при достаточном наборе сигналов; критические расхождения блокируют.
2. Aliases — публично только полезные варианты.
3. INN/OGRN — условная публикация.
4. Merge — полуавтоматический; unmerge обязателен.
5. ENTITY ≠ COMPANY PROFILE.
6. `/entity/{id}.json` в v1 не делаем.
7. При сомнении — не объединять; показывать needs_review / conflicts.
8. Отзыв не переносится только по названию.
9. При reassignment отзыва пересчитываются Analysis и AI Summary, provenance сохраняется.
10. Критические identity-конфликты блокируют автоматическое объединение независимо от confidence score.
11. Полный audit trail сохраняется при merge/unmerge.

### Утверждено Yumis (UX / PROFILE TEMPLATE v1.0)

1. Эталонный профиль строится вокруг Identity → Source Ratings → AI Summary → Analysis → единый список отзывов → Sources/Provenance.
2. Все отзывы компании публикуются одним общим списком; источник остаётся атрибутом отзыва.
3. Источники не становятся отдельными публичными разделами отзывов; фильтр по источнику допустим.
4. Общий «Рейтинг Отзовика» не показывается до появления собственной утверждённой методологии.
5. AI Summary визуально и смыслово отделён от оригинальных отзывов и не является рекомендацией.
6. Пустые, малые, stale, disputed, conflicted и unverified состояния показываются честно и без ложного ощущения полноты.
7. Для отсутствующих рейтингов использовать «Нет данных»/явную причину вместо пустого «—».
8. Главная страница — короткий лендинг с живым примером профиля как главным доказательством продукта.
9. Визуальное направление: Modern AI / Technology + Trust / Editorial; минимум декоративного шума.
10. Mobile-first progressive disclosure не должен скрывать критические identity, rating, Summary и review данные.
11. Темы и аналитика относятся к Analysis и могут использоваться как фильтры общего списка отзывов.
12. Публичный UX не должен молча объединять сущности, скрывать конфликты или выдавать AI Summary за первичный источник.

### Следующий архитектурный этап

После фиксации Identity Resolution следующий архитектурный этап — **SOURCE INGESTION / DATA COLLECTION**: получение отзывов из разных источников, нормализация и помещение в единый список компании без смешивания сущностей.

Для UX следующий этап — детализация компонентов и wireframes. Код и дизайн-система пока не создаются.

Добавлять новые архитектурные записи только после согласования.
