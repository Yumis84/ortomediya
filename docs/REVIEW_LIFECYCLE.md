Документ описывает жизненный цикл отзыва и правила его публикации в эталонном профиле.

---

## 1. Разделение статусов (критично)

Не смешиваем два разных события:

### A. Source Status (состояние в источнике)
Определяется фактическим состоянием исходной площадки:
- `active` — отзыв доступен в источнике
- `removed_from_source` — удалён источником
- `unavailable` — источник временно недоступен / отзыв не найден

### B. Otzovik Moderation Status (состояние в Отзовике)
Определяется нашей системой:
- `active`
- `disputed`
- `hidden`
- `restored`
- `deleted`

Эти два измерения хранятся **раздельно**.

---

## 2. Статусы и публикация

| Source Status | Moderation Status | Публично виден | Текст виден | Участие в Analysis / Summary |
|---------------|-------------------|----------------|-------------|------------------------------|
| active | active | да | да | полное |
| active | disputed | да | да + метка «Оспорен» | пониженный вес / отдельная маркировка |
| active | hidden | да (как факт) | нет | нет |
| removed_from_source | * | да (как факт) | нет | нет |
| * | restored | да | да | полное |
| * | deleted | минимальный след | нет | нет |

---

## 3. Disputed reviews (утверждено)

- Оспоренный отзыв **не удаляется** автоматически.
- Получает moderation status = `disputed`.
- В Analysis учитывается с **пониженным весом** либо отдельно маркируется.
- AI Summary **обязан** учитывать наличие спора.
- Отзыв не должен влиять на выводы так, будто его статус обычный.
- После окончательного решения статус и влияние пересчитываются.

---

## 4. Удалённые отзывы — публичный счётчик (утверждено)

- Отдельный крупный публичный счётчик удалённых отзывов **не показываем** на первом этапе.
- Факт удаления сохраняется в provenance / audit trail.
- У конкретного отзыва можно показать:  
  «Отзыв больше недоступен в исходном источнике».

Таким образом:
- не создаём ложного ощущения масштаба удалений;
- не скрываем историю;
- не используем удалённые отзывы как обычные актуальные.

---

## 5. Хранение полных текстов (утверждено)

- Полный текст хранится во **внутреннем слое**, если это допустимо по законодательству, условиям источника и нашей политике.
- Публичная публикация полного текста определяется отдельно для каждого источника и юридической модели.
- Архитектура позволяет хранить:
  - текущий текст;
  - исходный snapshot;
  - дату получения;
  - источник;
  - review_id;
  - статус;
  - историю изменений.
- **Бессрочное хранение сейчас не утверждается.**
- Сроки хранения выносятся в отдельную **Data Retention Policy** после юридической проверки.

---

## 6. Кто может менять status (утверждено)

### Автоматический сборщик
- Может обновлять **только Source Status**  
  (`active` / `removed_from_source` / `unavailable`).
- **Не имеет права** самостоятельно переводить отзыв в `disputed` или `hidden`.

### Moderation workflow
- Перевод в `hidden` / `disputed` происходит **только** через определённый moderation workflow.

### Компания
- **Не может** самостоятельно удалить отзыв или изменить его содержание.
- Может:
  - оспорить отзыв;
  - предоставить объяснение / доказательства;
  - запросить проверку.
- Финальное решение принимает Отзовик по установленной процедуре.

---

## 7. Влияние на Analysis и AI Summary

- `active` + source active → полное участие.
- `disputed` → пониженный вес или отдельная маркировка + обязательный учёт в AI Summary.
- `removed_from_source` / `hidden` / `deleted` → исключаются из текущего расчёта (или Summary содержит явную пометку).

При любом изменении статуса:
- обновляется `source_data_version`;
- Analysis и AI Summary помечаются устаревшими и пересчитываются.

---

## 8. Provenance и audit trail

При любом переходе создаётся событие:

```json
{
  "event_id": "...",
  "review_id": "...",
  "source_status_from": "active",
  "source_status_to": "removed_from_source",
  "moderation_status_from": "active",
  "moderation_status_to": "active",
  "changed_at": "2026-08-24T12:00:00Z",
  "reason": "source_deleted" | "user_report" | "company_dispute" | "moderation" | "legal" | "other",
  "actor": "collector" | "moderator" | "system",
  "notes": null
}
```

Исходный provenance сбора **никогда не удаляется**.

---

## 9. Фильтрация в едином списке

По умолчанию публичный список:  
`moderation_status in (active, disputed, restored)` + соответствующие source status.

Можно запросить включая факты `removed_from_source` / `hidden` (без текста).

Фильтры по source, оценке, периоду, филиалу работают поверх.

---

## 10. Связь с принципами

- FACT остаётся FACT даже после удаления в источнике.
- «Удалён источником» ≠ «Скрыт/оспорен Отзовиком».
- Analysis и AI Summary прослеживаются до review_id.
- Единый список отзывов не дробится по источникам.

---

## Утверждённые решения (Yumis, 2026-08-24)

1. Disputed — пониженный вес / маркировка, AI Summary обязан учитывать спор.
2. Публичный крупный счётчик удалённых — не показываем.
3. Хранение текстов — внутренний слой + отдельная Data Retention Policy позже.
4. Сборщик меняет только Source Status; moderation status — только через workflow.
5. Компания может только оспорить / запросить проверку, не удалять и не редактировать.
6. Source Status и Otzovik Moderation Status хранятся раздельно.
