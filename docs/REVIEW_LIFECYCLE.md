Документ описывает жизненный цикл отзыва и правила его публикации в эталонном профиле.

---

## 1. Статусы отзыва (`review_status`)

| Статус | Публично виден | Текст виден | Учитывается в Analysis / Summary | Описание |
|--------|----------------|-------------|----------------------------------|----------|
| `active` | да | да | да | Обычный опубликованный отзыв |
| `removed_from_source` | да (как факт) | нет* | нет (или с пометкой) | Удалён в исходном источнике |
| `disputed` | да | да / нет** | да (с пониженным весом или пометкой) | Оспорен |
| `restored` | да | да | да | Восстановлен после удаления/скрытия |
| `hidden` | да (как факт) | нет | нет | Скрыт нами (модерация / жалоба) |
| `deleted` | нет (или минимальный след) | нет | нет | Полное удаление (редко) |

\* Текст не показываем публично, если источник удалил.  
\*\* Зависит от политики спора (по умолчанию текст остаётся + метка «Оспорен»).

---

## 2. Правила публикации текста

- **active / restored** — полный текст + все метаданные.
- **disputed** — полный текст + явная метка «Оспорен» + (опционально) краткая причина.
- **removed_from_source / hidden** — публично:
  - факт существования отзыва;
  - статус;
  - provenance (источник, даты, source_url если ещё валиден);
  - rating (если был);
  - **без полного текста**.
- **deleted** — минимальный audit-след во внутреннем слое; публично может полностью исчезать.

Machine-readable слой и audit trail всегда сохраняют возможность понять историю.

---

## 3. Влияние на Analysis и AI Summary

- `active` и `restored` — полностью участвуют.
- `disputed` — участвуют с пониженным весом или с явным флагом в Evidence.
- `removed_from_source`, `hidden`, `deleted` — исключаются из текущего расчёта frequency / sentiment / Summary (или Summary содержит пометку об исключении).

При изменении статуса любого отзыва:
- обновляется `source_data_version`;
- Analysis и AI Summary помечаются как потенциально устаревшие и пересчитываются.

---

## 4. Provenance и audit trail

При любом переходе статуса создаётся запись:

```json
{
  "event_id": "...",
  "review_id": "...",
  "from_status": "active",
  "to_status": "removed_from_source",
  "changed_at": "2026-08-24T12:00:00Z",
  "reason": "source_deleted" | "user_report" | "moderation" | "legal" | "other",
  "actor": "system" | "moderator" | "company" | "source",
  "notes": null
}
```

Provenance исходного сбора **никогда не удаляется**.

---

## 5. Фильтрация в едином списке отзывов

Публичный список по умолчанию показывает только `active` + `disputed` + `restored`.

Пользователь (и AI через параметры) может запросить:
- включая `removed_from_source` / `hidden` (как факты без текста);
- только определённые статусы.

Фильтры по `source`, оценке, периоду, филиалу работают поверх статусов.

---

## 6. Связь с принципами

- FACT остаётся FACT даже после удаления в источнике (мы фиксируем, что отзыв существовал).
- Analysis и AI Summary всегда могут быть прослежены до конкретных `review_id`.
- Единый список отзывов не дробится по источникам.
