# IDENTITY RESOLUTION v1.0 (черновик)

**Репозиторий:** Yumis84/ortomediya  
**Связан с:** DATA_MODEL v1.0  
**Статус:** проектирование (требует утверждения)  
**Дата:** 2026-08-24

Как система понимает, что «Ортомедия», «ООО Ортомедия», «Ортомедия Калининград» и карточки в Яндекс / 2ГИС / Google — одна сущность.

---

## 1. Идентификаторы

| Уровень | Поле | Публичность |
|---------|------|-------------|
| Канонический | `otzovik_id` (ULID) | да |
| Человекочитаемый | `slug` | да |
| Внешние | `external_ids` (упрощённо в public) | частично |
| Алиасы | `aliases[]` | да |
| Юридические | `legal_name`, `inn`, `ogrn` | да (если есть) |

---

## 2. Правила матчинга (приоритет)

1. Точное совпадение `inn` / `ogrn` → 100 % match.
2. Совпадение `slug` + основной website.
3. Совпадение названия + адрес/телефон + источник.
4. Fuzzy match названия + гео (требует ручного подтверждения на первом этапе).
5. Все внешние ID хранятся с `confidence` и `verified_at` (внутренний слой).

При конфликте создаётся `duplicate_candidate` / задача на merge.

---

## 3. Публичное vs внутреннее

**Публично:**
- `otzovik_id`, `slug`, `name`, `aliases`, `legal_name`, `inn`/`ogrn` (если есть)
- упрощённые `external_ids` (id + url)
- `conflicts` (включая possible_duplicate)

**Внутренне:**
- полные confidence scores
- merge_history
- candidate scores
- identity_confidence

---

## 4. Возможный дубль

Если обнаружен возможный дубль:

- status_flag: `possible_duplicate`
- запись в `conflicts` с type `possible_duplicate`
- в internal — `duplicate_candidates[]`

AI видит флаг и описание конфликта.  
Автоматический merge на первом этапе **не** производится.

---

## 5. Связь с отзывами

Все отзывы привязаны к одному `company_id` = `otzovik_id`.

Если отзыв изначально относился к карточке, которая потом была смержена — сохраняется audit trail.
