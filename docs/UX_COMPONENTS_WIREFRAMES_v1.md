# OTZOVIK UX COMPONENTS & WIREFRAMES v1.0

Статический UX-прототип. Код и дизайн-система не входят в этот документ.

## 1. Главный принцип

Одна компания → один профиль → единый список отзывов.
Источник является атрибутом каждого отзыва, а не отдельным разделом отзывов.

AI Summary отделён от оригинальных отзывов и Analysis.
Общий «Рейтинг Отзовика» не показывается.

## 4. Компоненты

### Identity Card
Назначение: однозначно показать, о какой компании идёт речь.
Обязательно: название, география, статус идентичности/верификации.

### Source Ratings Matrix
Показывает только фактические рейтинги конкретных источников.
Не складывает их в единую оценку.

### AI Summary
Визуально отличается от отзывов.
Не использовать оформление, похожее на клиентский отзыв.
Всегда показывать объём данных, источники, confidence и дисклеймер.

### Review Card
Нейтральная редакционная карточка.
Источник заметен, но отзывы не группируются по источникам.

### Status Badge
Статусы: verified, unverified, low_volume, stale, data_conflict, needs_review, disputed, under_review.
Цвет и визуальная сила должны отражать серьёзность, но не создавать алармизм.

### Filter Bar
Фильтры не меняют принадлежность отзывов компании.
Они только меняют представление общего списка.

### Empty State
Никогда не использовать «—» там, где данных нет.
Использовать понятные состояния: «Нет данных», «Отзывы пока не собраны», «Источник временно недоступен».

## 5. Состояния компонента AI Summary

### 0 отзывов
Summary отсутствует. Текст: «Недостаточно данных для сводки».

### 1–4
Summary не генерируется. Только отзывы и метаданные.

### 5–9
Preliminary Summary. Обязательное предупреждение о малом объёме.

### 10–19
Обычный Summary с указанием количества.

### 20–49
Полноценный Summary.

### 50+
Полноценный Summary; при наличии истории — динамика.

Если один источник → дополнительный дисклеймер.
Если конфликт → Summary обязан упомянуть конфликт.
Если данные stale → Summary обязан учитывать свежесть.

## 6. Состояния профиля

| Состояние | UI-поведение |
|---|---|
| Нет отзывов | Empty state, без рейтинга и Summary |
| 1–5 | Отзывы, без общего рейтинга, минимум аналитики |
| 5–20 | Summary preliminary/limited |
| 20–100 | Полноценная аналитика |
| 100+ | Расширенная аналитика и динамика при наличии данных |
| Нет источника | «Нет данных» в конкретной ячейке |
| Конфликт | Badge + краткое объяснение |
| Stale | Badge + дата последнего обновления |
| Unverified | Независимый профиль, компания не подтвердила |
| Verified | Компания подтвердила профиль |
| Disputed | Явный статус спора |
| Under review | Статус проверки |
| Removed review | След удаления сохраняется |
| Несколько филиалов | Фильтр branch, общий список отзывов |
| Возможный дубль | needs_review, без молчаливого merge |

## 7. Mobile progressive disclosure

Первый экран: identity → основные source ratings → AI Summary → первые отзывы.

Далее: темы → фильтры → отзывы → о компании → источники → методология.

Фильтры открываются в bottom sheet или компактной панели.
Analysis может быть свёрнут.
AI Summary нельзя скрывать полностью при наличии Summary.

Machine-readable данные не зависят от визуального раскрытия блоков.

---

## 8. Trust rules

1. Не показывать пустые рейтинги как «—».
2. Не создавать визуальную иерархию, будто один источник является «истиной» без основания.
3. Не смешивать AI Summary с отзывами.
4. Не скрывать источник отзыва.
5. Не превращать количество отзывов в знак качества.
6. Не показывать общий рейтинг до утверждения собственной методологии.
7. При identity ambiguity не объединять компании молча.
8. Любое существенное утверждение AI должно быть проверяемым через Evidence.

---

## 9. Definition of Done для UX-шаблона v1

Шаблон считается готовым, если:
- одна компания имеет единый профиль;
- отзывы отображаются единым списком;
- источник виден у каждого отзыва;
- рейтинги отображаются только по источникам;
- AI Summary визуально отделён;
- пустые, stale, conflict и verification состояния имеют отдельные UI-состояния;
- mobile не теряет критические данные;
- UI не создаёт ложного общего рейтинга;
- layout способен работать для 0, 7, 50 и 300+ отзывов;
- возможный дубль не объединяется молча.

Код и дизайн-система будут отдельным этапом после утверждения UX.
